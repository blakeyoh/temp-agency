# Sweet 16 Enactment Directives

These are operator instructions for the implemented harness, derived from each
scrimmage's `Exact input`. They replace historical ad hoc commands and the old
10-opener brief. They are preparation, not start authorization or standing changes.

## Common dispatch boundary

Use the canonical `tail-test-s16.txt`, its readiness hash, the frozen definition and
contract, and the selected entrant's directive only. Produce exactly 24 numbered
rules within the 2,000-token proposal cap. Do not supply matchup, A/B assignment,
opponent, panel, verdict or tally. Follow `official-runs/README.md` for the frozen
model/effort and source template. Resolve unavailable runtime at readiness; do not
silently substitute another model.

The operator freezes inputs and exact hashes and commits a dispatch-log entry
before every tool call. Use an argument seed for seeded tools and JSON null for
NO_SEED tools. Later-stage inputs are committed when available, before their own
invocations. Record actual commands, stdout, failures, receipts and evaluator seals.
Never copy development receipts into the official directory. A passing tool receipt
establishes only its declared binding span, not general creativity or causation.

Keep all rejected attempts in the chain. Read each executable's `--help` for its
actual interface. Freeze real official input manifests rather than silently adopting
scrimmage examples. All implemented entrants must pass packet admission and the
full receipt gate; no evidence means no mechanism credit.
